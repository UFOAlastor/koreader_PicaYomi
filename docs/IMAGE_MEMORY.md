# 低内存图片阅读

墨水屏设备同时承担 Lua、网络子进程、压缩图片与像素缓冲的内存开销。仅限制图片宽高不足以覆盖长时间阅读；预算需要考虑当前可用内存、已保留的输入和显示缓冲。

`util/memory_guard.lua` 统一分配解码、渲染缓存和后台任务预算。Linux 读取 MemAvailable，读不到时保守退回设备策略。内存读数是观测，不能保证后续分配成功。回收后重新采样，再决定是否继续解码。

JPEG、WebP 优先在解码器内缩小。PNG 支持按行读取和区域输出；长图按视口处理，避免为不可见区域分配完整位图。源声明的分带图片处理通过 SDK 注册，由宿主组织区域还原与资源回收，平台协议不进入宿主。

阅读期间暂停封面与离线下载任务，退出后恢复；闲置子进程及时释放。已缓存的压缩输入只计入一次，临时位图在使用后释放。极低内存时保留原始文件并提示，恢复余量后可重试；不能将固定阈值视为设备硬件极限。

实现入口包括 `util/scaled_decode.lua`、`util/png_region.lua`、`source/image_service.lua` 与 `source/processors.lua`。较大的渐进式 JPEG 仍有低内存限制，其他设备的内存策略需要实际验证。
